Команда агентів

Capstone · LEAD оркеструє, агенти виконують. LEAD сам код не пише.

Розвилка — перше питання LEAD

Це йде у Storybook? LEAD питає це ЩОРАЗУ, щойно прилітає лінка або задача — до будь-якої роботи.
Так — це компонент
spec → builder → reviewer → storybook → ⏸ ОК → shipper
Компонент показуємо ізольовано: локальний Storybook + Chromatic-прев'ю. Пуш тільки після живого ОК.
Ні — застосунок / сторінка
spec → builder → reviewer → shipper
Storybook пропускаємо. Перевірка — на живій збірці, деплой Cloudflare з пушу.

Хто за що відповідає

spec
Аналітик
крок 01
Робить
Читає ТЗ і Figma-лінк, витягує токени й структуру, пише SPEC.md.
Віддає
Екрани, props, усі стани, поведінка, edge cases, адаптив, a11y-вимоги, acceptance criteria.
Зона
Єдине джерело правди для всіх наступних. Що не в SPEC — того не існує.
Не робить
Не пише код. Не вигадує вимоги — невідоме йде у «Відкриті питання».
builder
Розробник
крок 02
Робить
Реалізує SPEC на Vite + React + TypeScript. Повторює патерни проєкту.
Віддає
Код з усіма станами та edge cases, зелений tsc --noEmit і білд.
Зона
Чисто, просто, без over-engineering. Без зайвих залежностей. Без any.
Не робить
Не розширює scope. Не хардкодить секрети. Не рапортує «готово» на червоній збірці.
reviewer
Рев'ювер
read-only
Робить
Звіряє код з acceptance criteria SPEC, перевіряє кожен стан, базову a11y.
Віддає
Вердикт PASS або FAIL + нумерований список фіксів із file:line.
Зона
Ворота якості. Файли не чіпає — тільки читає й запускає перевірки.
Не робить
Не фіксить сам. Не валить за смаківщину — стиль це не FAIL.
storybook
Демонстратор
⏸ стоп на ОК
Коли
Тільки якщо на питання «це у Storybook?» відповідь ТАК.
Робить
Пише *.stories.tsx — по story на кожен стан. Піднімає локальний Storybook. Запускає npx chromatic.
Віддає
Лінк на локальну story + Chromatic build URL + preview URL.
Зона
Показати живий компонент людині до пушу. Токен — лише з env.
Не робить
Не комітить і не пушить. Зупиняється й чекає явного ОК.
shipper
Реліз
крок 05
Коли
Тільки після явного «ОК» від людини. Мовчання і PASS від reviewer — не ОК.
Робить
Перевіряє діф на секрети, feature-гілка, Conventional Commit, git push.
Віддає
Гілка + хеш, Chromatic build URL, live URL (Cloudflare), статус CI.
Зона
Єдиний, хто торкається remote. Chromatic і Cloudflare деплояться самі з пушу.
Не робить
Не комітить у main. Не вигадує URL. Не оголошує успіх на червоному CI.

Правила LEAD

  1. Прилетіла лінка або задача — перше питання завжди одне: це йде у Storybook чи ні. До цього ніяких агентів.
  2. Сам код не пишу. Уточнюю, розбиваю на кроки, делегую, зшиваю результати.
  3. Агенти йдуть строго послідовно — кожен спирається на артефакт попереднього.
  4. FAIL від reviewer → назад на builder зі списком фіксів. Повторюємо, поки не PASS.
  5. Гейт після storybook — жорсткий. Прев'ю показано, далі тиша, поки людина не скаже ОК.
  6. Нічого не публікується назовні без явного підтвердження.
